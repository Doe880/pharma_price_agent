# Мониторинг цен и маркетинговые исследования аптек

Проект автоматически проверяет карточки Apteka.ru и Здравсити для Москвы. Каталог содержит две формы Галавита, Amulapro, две версии Инстиго и Хепиклим форте. Актуальные позиции перечислены в разделе «Каталог мониторинга». Точное наименование формы хранится в `catalog.json`. Бренды сравниваются по цене заданных упаковок.

## Запуск в Windows и PyCharm

Распакуйте архив и откройте папку в PyCharm. Выберите Python 3.10 или новее. В PowerShell из папки проекта выполните:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe agent.py --no-ai
```

Откройте `data/prices_*.xlsx`. SQLite-файл `data/prices.sqlite3` хранит цены между запусками. В папке `example` находится актуальный пример расширенного отчёта по выбранным товарам. Новые срезы формируются командой `python agent.py`.

### OpenAI

Укажите переменную `OPENAI_API_KEY` в локальной конфигурации запуска PyCharm или в окружении PowerShell. Для ввода в PowerShell 5.1+ можно использовать:

```powershell
$env:OPENAI_API_KEY = (Get-Credential -UserName 'OpenAI' -Message 'Введите API-ключ в поле пароля').GetNetworkCredential().Password
.\.venv\Scripts\python.exe agent.py
```

По умолчанию используется `gpt-6-luna` через OpenAI Responses API. При необходимости задайте `OPENAI_MODEL` со значением другой модели, совместимой с Responses API и `reasoning.effort=none`. Эта переменная влияет на комментарий к ценам, аналитические листы используют Luna. Агент передаёт агрегаты по прямо проверенным аптечным карточкам. Текст модели попадает в комментарий Excel, а цены, наличие, медиана и изменения рассчитываются в Python. Без ключа или при ошибке API отчёт сохраняется с диагностикой.

Запускайте интеграцию с OpenAI в соответствии с [официальным списком поддерживаемых стран](https://developers.openai.com/api/docs/supported-countries). На момент пилота Россия отсутствовала в списке. Сбор и Excel можно запустить в режиме `--no-ai`.

## Ozon и Ютека

Автоматический сбор с Ozon и Ютеки требует доступного канала данных. В этой версии можно передать собственную выгрузку поставщика или заполнить шаблон `marketplace_feed.csv` по проверенным карточкам. Формат — CSV UTF-8 с разделителем запятой.

| Поле | Значение |
|---|---|
| source | `Ozon` или `Ютека` |
| sku | Ключ из `catalog.json` |
| city | `Москва` |
| seller | Точное имя продавца или аптеки |
| url | HTTPS-ссылка на карточку площадки |
| price_type | `public`, `from` или `card` |
| availability | `in_stock`, `out_of_stock` или `unknown` |
| observed_at | Фактическое время проверки в ISO 8601 с часовым поясом за текущую дату Москвы |
| price_rub | Цена упаковки. При `out_of_stock` оставить пустым |

```powershell
.\.venv\Scripts\python.exe agent.py --feed marketplace_feed.csv --no-ai
```

Проверяйте соответствие SKU исходной карточке при заполнении CSV. Агент валидирует поля и дату, а подтверждение продавца, цены и наличия в этом канале обеспечивает источник выгрузки. Импорт виден на листах «Проверки», «История» и «Изменения». Сводка минимума, медианы и максимума использует прямые публичные предложения с наличием. Сравнение за сутки строится между одинаковыми карточками одного продавца, канала и типа цены.

## Запуск по расписанию

Для постоянного сбора добавьте ежедневный запуск, например в 09:00 МСК, в Планировщик заданий Windows или в cron на сервере. Программа — полный путь к Python из виртуального окружения, аргумент — полный путь к `agent.py`. Задайте постоянный `--data-dir`, если данные нужно хранить вне папки проекта. Время в Excel указано по Москве.

Код завершения 2 означает, что часть или все прямые карточки завершились с ошибкой. Excel при этом сохраняется. Просматривайте лист «Проверки» и журнал запуска. В новой локации сначала проверьте, что сайты отдают нужный регион. Пилотные парсеры проверяют маркер Москвы в заголовке, а Здравсити использует общий регион «Москва и область». Географию за пределами Москвы потребуется проверить и добавить в адаптеры.

При расширении каталога создавайте новый ключ для новой комбинации бренда, дозировки, формы и размера упаковки. Идентификаторы источников и карточки проверяйте перед запуском. Для защищённых площадок используйте согласованный прайс-фид или разрешённую интеграцию.

## Маркетинговые исследования

Обычный запуск формирует расширенный Excel. Флаг `--prices-only` оставляет прежние четыре листа отчёта. Для первого запуска обновите зависимости из `requirements.txt`. История цен остаётся в `data/prices.sqlite3`. Для новых наблюдений и кеша разметки создаётся `data/research.sqlite3`.

| Листы | Что внутри |
|---|---|
| Отзывы по темам, Выборка отзывов | Бренд и точный SKU, количество отобранных и размеченных текстов, доля среди размеченных, до двух проверенных цитат и ссылки, вопрос для карточки или FAQ. Один отзыв может попасть в несколько тем. |
| Видимость, Позиции поиска, Потери видимости | Позиции, доля топ‑10 на проверенных запросах, охват из общего списка и сравнение только одинаковых запросов за две соседние даты. |
| Аудит карточек | Проверка дозировки, формы и размера упаковки по каталогу. Названия, ключевые слова описания и визуальный отпечаток основного фото сопоставляются между аптечными карточками. В отчёте указаны приоритет, значения, ссылки и действие для проверки. |
| Календарь промо, Частота промо | Акции, наборы и зачёркнутые цены, обнаруженные на карточках, срезы по датам, скидка при наличии двух сопоставимых цен, число уникальных промо, дней с промо и дней проверки за 30 дней. |
| Диагностика исследования | Покрытие источников, проблемы загрузки или обработки, статус Luna и определения показателей. |

### Сбор отзывов и работа Luna

Автоматически используются первые доступные отзывы с отдельных страниц Apteka.ru и данные карточек Здравсити. Лимит регулируется через `review_limit_per_card` в `research_config.json`. История копится между запусками, повторы с тем же SKU, аптекой, датой и текстом исключаются. Счётчик на витрине может включать больше отзывов, чем доступно сборщику. Выборка включает разные даты, которые видны на листе «Выборка отзывов».

Для разметки используется `gpt-6-luna`. Задайте `OPENAI_API_KEY` и запустите `agent.py` без `--no-ai`. В модель попадают текст отзыва, поисковая фраза или текст промомеханики и служебный номер. Метаданные об авторе не собираются, телефонные номера российского формата, ссылки и email маскируются. Цитата принимается только при дословном совпадении с обработанным текстом. Разметка кешируется. Параметр `max_ai_new_reviews` ограничивает число новых отзывов для обработки за запуск.

Excel формируется и без ключа. Новые отзывы получают статус «Ожидает разметки», запросы помечаются «Не размечено», а промо показывают механику по признакам сайта. Цены, позиции и аудит рассчитываются на стороне Python. Если ключ задан, цитаты отражают высказывания авторов и служат материалом для проверки вопросов покупателей. Сравнение описаний и фотографий — редакционный аудит карточек.

### Видимость в поиске аптек

`research_config.json` задаёт фиксированные города, поисковые фразы, целевые SKU и порог снижения доли. В пилоте установлен один город — Москва. Для остальных городов сначала добавьте город в конфигурацию и подготовьте соответствующие срезы, с фактической региональной выдачей. Для проверки цен город по-прежнему задаётся в каталоге.

В `robots.txt` Apteka.ru и Здравсити закрывают автоматический обход поисковой выдачи. Проект обрабатывает два согласованных входа:

- **CSV с позициями.** Возьмите разрешённую выгрузку или вручную заполните шаблон `visibility_feed.csv`. Запишите одну строку для каждого целевого SKU в срезе. `source` — `Apteka.ru` или `Здравсити`; `city` и `query` из конфига; `observed_at` содержит дату и часовой пояс; `result_url` — URL результатов. `position` — позиция товарной карточки, начиная с 1; `depth` — сколько позиций проверили. Для `not_found` оставьте позицию пустой, для `error` укажите глубину 0. Если товар найден, укажите `found`. Пример команды: `python agent.py --visibility-feed visibility_feed.csv --no-ai`.
- **Сохранённый HTML поисковой страницы.** Откройте сайт вручную, выставьте нужный город, выполните запрос и сохраните страницу в HTML UTF‑8. В `search_snapshots.csv` внесите `source,city,query,observed_at,result_url,html_path`. `html_path` может быть путём относительно CSV. Парсер проверяет признаки запроса и города, берёт порядок уникальных товарных карточек из списка и записывает позиции целевых SKU. Если разметка страницы не распознаётся, используйте CSV. Пример команды: `python agent.py --search-snapshots search_snapshots.csv --no-ai`.

Выберите для каждого среза один способ импорта. Импорт принимает срезы за текущую дату Москвы. Глубина меньше десяти засчитывается в долю топ‑10, если целевой SKU действительно найден. Если SKU не найден, нужны просмотренные десять позиций. Ошибки и пропуски видны в подробном листе. Для сравнения по площадкам используйте одинаковые запросы, время и одинаковый подход к учёту промопозиций.

### Как читать календарь промо

«Впервые замечена» и «Последний раз» — даты фактических наблюдений. Скидка рассчитывается как разница между зачёркнутой и текущей ценой, делённая на зачёркнутую цену. Для комплектов используется цена всего комплекта. Если исходная цена отсутствует, скидка остаётся пустой. Отчёт охватывает промо, показанные на проверяемых карточках, включая блоки выгодных наборов. Частота отражает уникальные обнаруженные промопредложения и количество дней, в которые они встречались.

## Дашборд Streamlit

В терминале PyCharm или PowerShell из папки проекта выполните:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dashboard.txt
.\.venv\Scripts\python.exe -m streamlit run dashboard.py --server.address localhost
```

Также можно открыть `start_dashboard.bat` после установки зависимостей. Интерфейс доступен на [http://localhost:8501](http://localhost:8501). Графики построены по готовым Excel-отчётам. Дашборд открывает последний отчёт из `data`, позволяет выбрать более ранний и скачать его. Если отчётов ещё нет, открывается пример из папки `example`. Для нестандартного `--data-dir` задайте ту же папку переменной окружения `PHARMA_DATA_DIR` перед запуском Streamlit.

Чтобы обновить данные через интерфейс, нажмите **«Собрать свежие данные»** в боковой панели. При необходимости оставьте включённым интернет-мониторинг. Через несколько минут новый Excel-отчёт автоматически появится в списке и откроется. Пока сбор идёт, дождитесь его завершения. Альтернатива — запуск `agent.py` командой или по вашему расписанию и обновление списка отчётов. Ключ OpenAI нужен агенту при разметке, а графики используют имеющиеся данные. Вкладка «Видимость» появится с заполненными показателями после импорта поисковых срезов. Фильтр города относится к ценам, видимости и промо. Отзывы и аудит относятся к карточкам товара.

## ИИ сводка в дашборде

На вкладке «ИИ-сводка» нажмите «Сформировать ИИ-сводку». Luna получает агрегированные показатели текущего отчёта и выбранных фильтров по аптечным разделам и интернет-агрегатам выбранных брендов. Тексты отзывов и цитаты, имена авторов, ссылки и API-ключ в аналитические данные не входят. Текст сводки можно скачать в Markdown.

Задайте ключ через поле «API-ключ» в боковой панели или скопируйте `.env.example` в `.env` рядом с `dashboard.py` и заполните `OPENAI_API_KEY`. После изменения файла перезапустите дашборд. Поле ввода скрывает символы. Ключ из поля используется в текущем окне, а сохранённые сводки содержат только ответ модели и время его получения.

Сводка запрашивается по кнопке. Результат сохраняется в `data/dashboard_summaries.sqlite3` и повторно открывается для тех же показателей, отчёта и фильтров. При выборе другого отчёта или набора SKU дашборд показывает соответствующий результат либо предлагает создать новый. В примере с неразмеченными отзывами и без поисковых срезов модель получает информацию об этих пробелах.

Масса саше и капсул указывается для идентификации товара и сопоставления карточек. В дашборде форма выпуска включена в подпись товара. Обе версии Инстиго отслеживаются отдельно.

Лонгидаза и Суперлимф исключены из текущего каталога и поисковых запросов. В новых отчётах и текущих фильтрах дашборда отображаются товары из каталога. Прежняя SQLite-база поддерживается, история в отчёт выбирается только для актуальных SKU.

Проверка наличия выполняется при каждом сборе. При отсутствии товара цена не используется в сравнении публичных предложений.

## Полные тексты отзывов

Вкладка «Отзывы» сразу показывает таблицу собранных отзывов. В ней есть товар, аптека, дата публикации, полный текст, ссылка, темы и статус разметки. Одна строка соответствует одному отзыву. Можно выбрать аптеку и найти слово или фразу в тексте. Тексты доступны после сбора даже без ключа OpenAI, темы появляются после обработки Luna.

В новых Excel-отчётах тексты находятся на листе «Тексты отзывов». Если выбран старый отчёт с одними цитатами, сформируйте новый обновлённым агентом. Накопленные отзывы из research.sqlite3 будут включены в новый отчёт для актуальных SKU. Количество текстов зависит от того, какие отзывы доступны на сайтах аптек.

## Интернет-мониторинг

Вкладка **Интернет** добавляет семь направлений для Галавита, Амула Про, Инстиго и Хепиклим форте:

| Раздел | Что сохраняется |
| --- | --- |
| Упоминания | Подтверждённые страницы, домены, дата публикации (если есть), первое обнаружение и проверка; одинаковые и близкие тексты объединяются |
| Вопросы | Опубликованные вопросы и FAQ со ссылками; это не статистика спроса |
| Материалы | Публикации и карточки; Luna размечает тему, аудиторию и основное сообщение |
| Реклама | Текст обнаруженных предложений, механика и найденная маркировка; не измеряет расходы и показы |
| Поиск | Источники OpenAI без позиции; числовые позиции Brave Search или фактической CSV-выдачи |
| Ассортимент | Названия, формы, масса/дозировка и упаковки; первое наблюдение требует проверки, это не дата запуска |
| Сравнение брендов | Числа материалов, площадок, вопросов, предложений и ассортиментных позиций в собранных источниках |

В настройках вкладки можно добавить бренды для сравнения и публичные URL. Лонгидаза и Суперлимф не возвращены в аптечный каталог. Хепиклим форте 645 мг, капсулы №30 добавлен в каталог, запросы видимости и все общие фильтры. Для него пока подключена одна проверенная карточка Apteka.ru: сравнение карточек разных аптек появится после подключения второго источника.

```bash
# Все аптечные и интернет-таблицы, без платных вызовов OpenAI
python agent.py --no-ai
# Только интернет; без поиска новых URL и без ИИ
python internet_monitor.py --no-ai --no-search
# Импорт согласованного списка страниц и фактической поисковой выдачи
python internet_monitor.py --urls internet_urls.csv --search-csv internet_search.csv
# Прежний сбор без интернет-мониторинга
python agent.py --skip-internet
```

Источники, алиасы, страна/город и лимиты задаются в `internet_config.json`. Начальные источники включают официальные сайты, новости производителя, отраслевые публикации, страницу отзывов и промо Apteka.ru. Поддержаны HTML, RSS/Atom и XML sitemap (тип `feed`). JavaScript, авторизация, PDF и закрытые страницы не обрабатываются. Ошибки и ограничения обхода видны в проверках источников. Соблюдаются robots.txt, паузы, ограничения размера ответа и числа страниц. Неудачная повторная проверка не удаляет предыдущую запись: смотрите дату последней успешной проверки.

Без ключа парсер работает по заданным URL. С `OPENAI_API_KEY` используется `gpt-6-luna`: Responses API, web search для обнаружения URL, структурированная разметка текста и кэш по хэшу содержимого. Модель не заменяет загрузку страницы: неподтверждённые страницы не входят в упоминания. Найденные поиском ссылки сохраняются отдельно. Бюджет по умолчанию: до 30 страниц, 3 поисковых запросов и 4 пакетов разметки по 8 страниц за запуск. Поисковые запросы чередуют бренды между запусками. Web search и токены оплачиваются по тарифу провайдера; числовой лимит расходов не установлен.

Для упорядоченной поисковой выдачи можно дополнительно задать `BRAVE_SEARCH_API_KEY`. Позиции относятся к Brave, не к Яндексу/Google; страна применяется к запросу, город хранится как контекст исследования, геолокация города в Brave не гарантирована. Для Яндекса/Google используйте согласованную выгрузку. Шаблоны: `internet_urls_template.csv`, `internet_search_template.csv`. Поля CSV поиска: `brand,query,provider,region,observed_at,url,title,position,depth`; дата ISO 8601 с часовым поясом, позиция 1…depth. Подтверждённая пустая выдача: пустые URL/позиция и depth=0. Шаблон без строк специально не содержит вымышленных результатов.

SQLite `data/internet.sqlite3` хранит историю обнаружений, поисковые срезы, кэш и диагностику. `internet_snapshot.json` используется дэшбордом; CLI добавляет восемь интернет-листов в общий Excel. ИИ-сводка получает агрегаты по выбранным брендам и дату интернет-среза. Обновление интернета по кнопке сохраняет JSON; новый общий Excel создаётся следующим запуском `agent.py`. Настройки из вкладки действуют для кнопки обновления; CLI использует переданный JSON-конфиг.

Для Streamlit Cloud задайте `OPENAI_API_KEY` и, при необходимости, `BRAVE_SEARCH_API_KEY` через Secrets как переменные окружения. Ключи не сохраняются в настройках и отчётах. Локальные файлы Streamlit Cloud могут исчезнуть при перезапуске: для долговременного мониторинга запускайте сбор в окружении с постоянным хранилищем. Автоматическое расписание этот модуль не создаёт.

Проверки: `python -m unittest discover -s tests -v`.

Пример от 24.11.2026: аптечный сбор 10/10 карточек и 201 текст отзыва; интернет-пример разобран из сохранённых HTML и помечен как архивный. Живые вызовы OpenAI/Brave в примере не выполнялись, поисковые позиции не заполнены.


### Дополнительные источники: отраслевые СМИ, Threads и поисковики

В `internet_config.json` подключены группы доменов: **Фармвестник**, **Vademecum**, **Remedium**, **Катрен Стиль**, **ФармМедПром** и **Threads** (`threads.com`, `threads.net`). В настройках вкладки «Интернет» виден список групп, в таблице упоминаний — категория и канал с фильтром. Основные сайты и известные публикации добавлены в стартовый список. Поисковые запросы учитывают алиасы брендов, включая Amulapro, и чередуют общий веб-поиск, Threads и отраслевые домены. Каждый запуск проверяет часть списка: это мониторинг выборки, а не гарантия полного охвата интернета.

**Поисковые API.** В дэшборде можно выбрать OpenAI / Brave, Google и Яндекс. В CLI выбор задаётся полем `search_providers`: `auto`, `google`, `yandex`. `auto` использует Brave при наличии его ключа, иначе OpenAI. Для Google и Яндекса добавьте `SERPAPI_API_KEY` в окружение / Streamlit Secrets. Это отдельный сервис с собственным тарифом, ключ OpenAI его не заменяет. Используются документированные [Google Search API](https://serpapi.com/search-api) и [Yandex Search API](https://serpapi.com/yandex-search-api). Обрабатывается первая страница органических результатов, до 10 строк, реклама не участвует в позициях. Сохраняются позиции провайдера без перенумерации. `google_location` задаёт расположение Google (по умолчанию Moscow,Moscow,Russia), `yandex_region_id` — код региона Яндекса (213 для Москвы). При смене города обновите оба поля. В строках поискового отчёта сохраняется фактически запрошенный регион. Срезы разных провайдеров/запросов не считаются одним сравнением.

**Threads.** Без токена выполняется поиск индексируемых страниц через выбранные поисковые API. Ограниченные страницы остаются ссылками в поисковом отчёте, если текст невозможно подтвердить. Дополнительно поддержан [официальный Keyword Search API](https://developers.facebook.com/documentation/threads/keyword-search): создайте приложение Meta с Threads, получите пользовательский токен с `threads_basic` и одобренным `threads_keyword_search`, затем задайте `THREADS_ACCESS_TOKEN`. Без одобренного разрешения поиск может охватывать только собственные посты авторизованного пользователя; наличие токена не подтверждает полноту доступа. Токен нужно продлевать по правилам Meta. Код выполняет только чтение публичных постов и не публикует сообщения.

Кнопка «Получать публичные посты через Threads API» включает прямой поиск по очереди брендов и алиасов. По умолчанию — до 2 запросов по 20 постов за запуск (`max_threads_queries`, `threads_posts_per_query`), сортировка RECENT, без обхода последующих страниц. Сохраняются текст, ссылка и дата публикации; короткие посты допустимы. Контакты маскируются. Вопросы из текста поста отмечаются как «Пост Threads», отдельно от FAQ. Недостающий токен или ошибка разрешений видны в диагностике. Флаг `--no-search` отключает и поисковые API, и прямой API Threads; `--no-ai` отключает OpenAI, но не внешние API с собственными ключами.

Лимит 3 веб-поисковых запроса сохранён **суммарно** по провайдерам, а не на каждый поисковик. Запросы, провайдеры, бренды и стартовые сайты ротируются между запусками. До 30 страниц / постов проходят сохранение и разметку за один запуск. Неподключённые провайдеры пропускаются с диагностикой. API-ключи и токены не записываются в отчёты или настройки. Реальные вызовы SerpApi и Threads требуют ваших ключей; тесты используют фиктивные ответы API.

Проверка доступности 24.11.2026: открылись страницы Фармвестника, Vademecum и Remedium; для известных публикаций Фармвестника и Remedium подтверждено упоминание Галавита. Катрен Стиль вернул HTTP 503, ФармМедПром запрещает проверенный обход в robots.txt — их доступность не гарантируется, обход ограничений не выполняется. Даты старых публикаций сохраняются исходными: обнаружение старой статьи не означает новую активность бренда.


### Общий сбор из Streamlit

В боковой панели появился блок «Обновление данных». Кнопка **«Собрать свежие данные»** запускает цены, отзывы, аудит и промо по всему каталогу. Фильтры товаров в интерфейсе относятся к просмотру готового отчёта. Флажок «Включить интернет-мониторинг» добавляет интернет-материалы в тот же Excel. Настройки брендов для сравнения и дополнительных URL берутся из настроек вкладки «Интернет»; провайдеры и лимиты — из `internet_config.json`.

По умолчанию общий сбор работает **без платных API**: цены и тексты отзывов собираются, ИИ-разметка и API-поиск отключены. Для Luna и подключённых поисковых API отметьте **«Использовать подключённые API (ИИ и поиск)»**. Ключ OpenAI можно указать в боковой панели или Secrets; другие ключи и токены берутся из окружения / Secrets. Они передаются процессу через окружение, не через аргументы команды и не через файлы настроек.

После успешного сбора новый отчёт выбирается автоматически, надпись «Демонстрационный срез» исчезает. При недоступности части аптечных карточек новый отчёт всё равно открывается с предупреждением; проверяйте листы диагностики. Значения позиций в аптечной выдаче требуют импорта фактических срезов, кнопка не заменяет такой источник.

Одновременно можно запустить один общий сбор на папку данных; повторный запуск блокируется. Сбор ограничен 20 минутами, после ошибки или тайм-аута блокировка снимается. При аварийном перезапуске приложения оставшаяся блокировка действует до 21 минуты. Сбор выполняется в процессе сервера и не является постоянной фоновой очередью: при перезапуске / остановке Streamlit он может прерваться. Данные Streamlit Cloud могут исчезнуть при пересоздании окружения; при необходимости скачайте Excel кнопкой «Скачать Excel».

Для CLI добавлены `--output путь/отчёт.xlsx` и `--no-internet-search`. Сочетание `--no-ai --no-internet-search` отключает OpenAI, поисковые API и Threads API, сохраняя обход заданных страниц. Кнопка доступна и при отсутствии готовых отчётов.
